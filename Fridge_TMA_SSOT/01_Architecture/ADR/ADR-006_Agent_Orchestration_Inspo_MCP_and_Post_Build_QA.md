# ADR-006: Агентная оркестрация, мандат MCP Inspo и автоматический Post-Build QA

## 1. Контекст и проблематика
При разработке Telegram Mini App «Свежесть» проявились следующие критические архитектурные и процессные дефекты:
1. **Размытие ролей (Архитектурный дрифт):** Архитектор вместо декомпозиции и выдачи формальных спецификаций агентам начал напрямую модифицировать кодовую базу (`replace_file_content` в `App.tsx`, `ProductCard.tsx` и др.). Это привело к появлению поверхностного типового кода («нейрослопа»), визуальным багам и нарушению принципа разделения ответственности.
2. **Игнорирование дизайн-референсов (Нейрослоп):** Несмотря на установленный MCP-сервер `inspo`, интерфейс собирался на типовых Tailwind-шаблонах без кинематики, fluid-анимаций, spring-переходов и выверенной типографики.
3. **Отсутствие автоматического контура верификации:** Сборки не проходили автоматический аудит специализированным QA-агентом после каждого этапа, из-за чего дефекты верстки и нестыковки состояний попадали пользователю.
4. **Острое ограничение квоты:** Остаток недельного лимита токенов составляет ~5%, что требует экстремальной токен-экономии и отказа от многословных холостых рассуждений.

---

## 2. Принятые решения

### Решение 1: Абсолютный запрет на прямой кодинг для Архитектора
- Архитектор — это координатор, системный проектировщик и приемочная комиссия.
- Архитектор **НИ ПРИ КАКИХ ОБСТОЯТЕЛЬСТВАХ** не пишет код в директориях `frontend/`, `worker/`, `scripts/`.
- Единственная зона ответственности Архитектора:
  1. Актуализация SSOT в `Fridge_TMA_SSOT/` и `BIG-PICTURE.md`.
  2. Формирование формальных контрактов и заданий для специализированных агентов.
  3. Запуск специализированных агентов (`frontend_lead`, `cloud_integrations`).
  4. Запуск QA-субагента (`qa_hygiene_operator`) для валидации результатов сборки.

### Решение 2: Мандат использования MCP-сервера Inspo для Frontend Lead
- Перед написанием или модификацией любого UI-компонента или экрана агент `frontend_lead` **ОБЯЗАН** выполнить вызов MCP-сервера `inspo`:
  - `recommend` (с параметрами `mode: "dark"`, `device: "mobile"`) или `search_screens`.
  - `find_components` и `get_reference_jsx` для заимствования кинематики, структуры карточек, микро-анимаций и шрифтовых сеток реальных продакшн-приложений (Linear, Cron, Apple Health).
- Запрещено использовать дефолтные "сырые" AI-стили (дешевые фиолетовые градиенты, шумные размытые тени, статичные неанимированные списки).
- Обязательны микро-анимации (spring-переходы, плавный swipe-to-action, tactile feedback via `Telegram.WebApp.HapticFeedback`, микроскейл `active:scale-[0.985]`).

### Решение 3: Обязательный контур Post-Build QA Subagent
- После каждого изменения кода исполнительным агентом Архитектор инициирует вызов QA-субагента (`qa_hygiene_operator` / subagent).
- QA-субагент выполняет чек-лист:
  1. `npm run build` (чистый билд TypeScript без warning/error).
  2. `npm run lint` (ESLint 0 ошибок).
  3. `npx vitest run` (все 25+ тестов зеленые).
  4. Проверка критериев Anti-Slop (соответствие токенам Zinc-950, микроконтрасты 1px hairline border, семантические цвета свежести).
- Только после получения вердикта `VERIFICATION: PASS` изменения фиксируются в Git и принимаются Архитектором.

### Решение 4: Токен-экономия (Стратегия 5% квоты)
- Исполнительные субагенты запускаются с минимально необходимым контекстом (JIT-доставка спецификации из SSOT).
- Вычислительные профили: `flash` для разработки, `flash_lite` / low-thinking для QA.
- Запрет на раздутые диалоги: формулировки лаконичны, фокус только на исполнении и проверке.

---

## 3. Последствия и проверка
- **Позитивные:** Полная ликвидация «нейрослопа», кинематика и анимации уровня топовых iOS/TMA приложений, детерминированная проверка качества на каждом шаге, строгая сохранность лимитов API.
- **Ограничения:** Требует строгого соблюдения агентного протокола без попыток "срезать угол" ручными правками.
